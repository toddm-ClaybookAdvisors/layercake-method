# Game Context

---

## Overview
This project is a **turn-based grid-based strategy/stealth game** where a player navigates a procedurally generated map, avoiding or outmaneuvering an adversary, while interacting with environmental hazards such as traps.  
The core emphasis is on:
- **Deterministic gameplay** for consistent outcomes and repeatable debugging.
- **Auditable code** for feature development and testing.
- **Modularity** for easy addition of new mechanics and entities.

---

## Core Architecture

### 1. Configuration (`config.json`)
- **Purpose**: Centralized game settings controlling map size, viewport size, UI text, controls, and procedural generation parameters.
- **Key Contents**:
  - **Map Dimensions**: `map_width`, `map_height` define overall game area; viewport defines visible region.
  - **Entity Attributes**:
    - Player: health, speed, vision radius.
    - Adversary: pathfinding limits, vision radius, reveal duration after trap triggers.
  - **Gameplay Mechanics**:
    - Trap placement ratios, trail slowdown effects, and vision reveal radius.
  - **Visual Representation**: ASCII-like characters for all elements (`†` for player, `X` for adversary, `T` for trap, arrows for direction).
  - **Colors**: Mapping for curses rendering color pairs.
  - **UI Strings**: Messages for events, overlays, and controls.
  - **Input Mapping**: W/A/S/D for movement, Q to quit; support for arrow keys via cardinal and diagonal directions.
  - **Map Generation Parameters**: Number of rooms, tile symbols (`#` walls, `.` floor), connectivity algorithms, and optional seed for deterministic generation:contentReference[oaicite:0]{index=0}.

---

### 2. Game Loop (`game.py`)
- **Purpose**: Main driver for the turn-based flow.
- **Core Responsibilities**:
  1. Initialize game state and load configuration.
  2. Enter main loop:
     - Capture player input.
     - Validate and process movement or actions.
     - Update adversary behavior (pathfinding toward player or patrol).
     - Handle environmental effects (traps, trails).
     - Check win/loss conditions.
     - Render the updated game state using `renderer.py`.
  3. Maintain deterministic timing for debugging and testing.
- **Interaction**:
  - Interfaces with `renderer.py` for visual updates.
  - Calls entity behaviors from `entities.py`.
  - Uses map structures generated by `mapgen.py`.

---

### 3. Entity System (`entities.py`)
- **Purpose**: Defines players, adversaries, traps, and trails.
- **Key Features**:
  - Player attributes: position, health, vision radius.
  - Adversary attributes: vision radius, pursuit logic, and temporary reveal after traps.
  - Environmental entities: traps (noise traps that reveal or slow entities), trails (temporary slow zones).
- **Design Goals**:
  - Modular to support new entity types or AI behaviors.
  - Easily testable, with `test_entities.py` covering core mechanics.

---

### 4. Procedural Map Generation (`mapgen.py`)
- **Purpose**: Creates dungeon-style maps based on room-and-corridor algorithms.
- **Features**:
  - Room creation with min/max size constraints.
  - Connection algorithms: default or variations like minimum spanning tree (`mst`).
  - Deterministic generation via optional seed.
- **Outputs**:
  - Tile grid representing walls, floors, and connected pathways.
  - Data used by `renderer.py` and `entities.py` for positioning and pathfinding.

---

### 5. Rendering System (`renderer.py`)
- **Purpose**: Visual representation of game state.
- **Features**:
  - ASCII-based rendering using curses or similar terminal interface.
  - Color-coded elements:
    - Player, adversary, traps, alerts, arrows.
  - Overlays:
    - Stats (health, speed, vision).
    - Overlay format: layer, tick, FPS, and player position.
- **Design Goal**:
  - Keep visual updates efficient and easy to extend (e.g., for debugging overlays or mini-maps).

---

### 6. Utilities (`utils.py`)
- **Purpose**: Shared helper functions (e.g., vector math, pathfinding support, utility classes).
- **Use Cases**:
  - Reducing duplication across map generation, entities, and game loop.

---

### 7. Testing (`test_entities.py`)
- **Purpose**: Unit tests validating entity behavior and interactions.
- **Scope**:
  - Player movement and collisions.
  - Trap triggering and effects.
  - Adversary pursuit and reveal logic.

## Gameplay Flow (Example)

### **Typical Turn**
1. **Player Action**:
   - Input via W/A/S/D keys.
   - Move to a tile or attempt interaction.
2. **Environment Update**:
   - Trigger traps if stepped on.
   - Leave a player trail (may slow the adversary later).
3. **Adversary Update**:
   - Pathfind toward player or continue patrol.
   - If player triggered noise trap → adversary moves aggressively toward location.
4. **State Evaluation**:
   - Victory: player reaches the exit.
   - Defeat: adversary catches the player.
5. **Rendering**:
   - Update viewport to reflect new positions, trails, alerts, and stats.
6. **UI Feedback**:
   - Display relevant messages (`victory`, `defeat`, `noise_trap_player`, etc.).

## Key Use Cases
1. **Stealth Navigation**:
   - Avoid adversary detection by using vision radius knowledge.
   - Use trails strategically to mislead.
2. **Trap Interaction**:
   - Navigate around traps or deliberately trigger them to manipulate adversary behavior.
3. **Debugging & Replay**:
   - Deterministic map generation and movement for consistent testing.
   - Replay logs to confirm AI or player behavior after changes.
4. **Map Expansion**:
   - Adding new room types or connectivity algorithms (e.g., sparse maps).
5. **Entity Extensions**:
   - New entity types (e.g., neutral NPCs, power-ups, alternate adversaries).
